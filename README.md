# Pytest 实战学习笔记
## Chapter 01 Pytest 基础认知
### 核心设计理念
1. 测试用例之间**完全相互隔离**，互不干扰
2. 原生使用断言语法判定结果，无需额外断言库
3. 单条用例独立收集控制台IO输出、运行日志，便于问题定位
4. 主流测试模式支持：数据驱动测试、行为驱动测试、关键词驱动测试
5. 常用测试类型：冒烟测试、步进测试、回归测试、增量测试

### 测试用例执行方式
1. 终端直接执行：`pytest` 系列命令运行用例
2. 代码内调用启动函数，程序化执行测试

### 用例执行输出内容
1. 测试运行环境信息
2. 测试用例自动收集统计情况
3. 整体用例执行进度与状态
4. 失败/异常用例详细报错信息
5. 最终整体测试结果统计摘要

### 自动收集用例规则
- 自动忽略：`venv` 虚拟环境目录、`.` 开头隐藏文件夹内测试代码
- 识别文件：以 `test_` 开头 / 以 `_test` 结尾 的 `.py` 测试文件
- 识别测试类：以 `Test` 开头定义的测试类，**禁止定义`__init__`构造方法**
- 识别测试函数/方法：`test_` 开头命名，无入参、无返回值

## Chapter 02 命令行参数、配置与用例标记
### 常用命令行参数
| 参数 | 作用说明 |
| ---- | ---- |
| `-h/--help` | 查看 pytest 全部帮助指令 |
| `-x` | 遇到用例失败立即停止整体测试，快速失败 |
| `-v` | 提升终端输出日志详细等级，展示用例执行名 |
| `-s` | 关闭控制台IO捕获，直接打印代码内`print`内容 |
| `-m` | 根据自定义标签筛选指定测试用例执行 |

### 配置文件
统一管理 pytest 全局运行规则、标签注册、默认执行参数等，统一团队测试环境。

### 测试标记体系
作用：实现用例筛选、运行逻辑增强、执行条件控制
1. **自定义用户标记**
    - 仅用于筛选用例，无内置执行逻辑
    - 使用流程：配置文件注册标签 → `@pytest.mark.xxx` 装饰用例 → 命令行 `-m` 筛选执行
2. **内置官方标记**
    - `@pytest.mark.skip`：无条件跳过当前测试用例
    - `@pytest.mark.skipif`：满足指定条件时跳过用例
    - `@pytest.mark.xfail`：标记用例为**预期失败**，不判定为测试故障
    - `@pytest.mark.parametrize`：实现参数化测试，核心实现数据驱动
    - `@pytest.mark.usefixtures`：无参形式快速引入Fixture前置后置

## Chapter 03 Fixture 核心机制
### Fixture 两大核心能力
1. 灵活实现测试**前置/后置**自动化操作
2. 完成测试数据、环境对象、工具实例**内容注入**

### Fixture 编写流程
1. 定义普通Python函数
2. 函数上方添加 `@pytest.fixture` 装饰器
3. 函数内使用 `yield` 分割**前置逻辑**与**后置清理逻辑**

### Fixture 正确调用规则
1. 仅允许**测试用例主动调用**Fixture，禁止反向调用
2. 调用方式：用例形参声明 / 装饰器标记引入
3. 禁止在业务代码中直接手动调用Fixture函数

> 报错区分：Error = Fixture前置/后置代码异常；Failure = 测试用例自身断言失败

### Fixture 作用域（共享范围）
优先级从小到大：
1. `function`：函数级别，单条用例独立生效（默认级别）
2. `class`：测试类级别，类内所有用例共享
3. `module`：模块级别，单个`.py`文件内所有用例共享
4. `package`：包级别，同级目录包内用例共享
5. `session`：会话级别，**全局所有测试用例共享**
6. `conftest.py`：跨文件全局共享Fixture， pytest自动向上检索，实现目录级环境注入

> Fixture 具备面向对象封装特性，可分层封装测试环境

### 数据注入规则
通过 `yield` 关键字向外返回数据/实例，**单条测试用例仅支持单次注入**

## Chapter 04 主流实用插件
1. `pytest-html`：一键生成静态HTML可视化测试报告
2. `pytest-xdist`：多进程分布式并发执行，大幅提升大批量用例执行效率
3. `pytest-order`：自定义控制测试用例先后执行顺序
4. `pytest-rerunfailures`：自动重跑执行失败的测试用例
5. `pytest-result-log`：持久化记录每条用例执行结果至日志文件
6. `allure-pytest`：生成Allure标准测试数据，搭建高颜值交互式测试报告
